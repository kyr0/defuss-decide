# Adapter-PoC 0.2 · validation and provenance

Validated 2026-11-01. The reports are in `reports/tasks/`; the large model artifacts are regenerated by the scripts in `python/`. Python and JS compare **the same pinned real checkpoint**, not a random or miniature replacement model.

## Sources and implementation

- Text checkpoint: [vllm-sr/vela3-fast](https://huggingface.co/vllm-sr/vela3-fast), revision `fa60e3aa41132c60bf05a84cabfdced39cb6d4f7`.
- Vision checkpoint: [vllm-sr/vela3-fast-vision](https://huggingface.co/vllm-sr/vela3-fast-vision), revision `c1f651cafddca43860a855ee434a35697949bce1`.
- [Text schema encoder and decoder](https://huggingface.co/vllm-sr/vela3-fast/blob/fa60e3aa41132c60bf05a84cabfdced39cb6d4f7/vela3_schema.py), [routing](https://huggingface.co/vllm-sr/vela3-fast/blob/fa60e3aa41132c60bf05a84cabfdced39cb6d4f7/vela3_encoder.py).
- [Vision adapters, formatting and region decoding](https://huggingface.co/vllm-sr/vela3-fast-vision/blob/c1f651cafddca43860a855ee434a35697949bce1/uvb_core.py), [vision API](https://huggingface.co/vllm-sr/vela3-fast-vision/blob/c1f651cafddca43860a855ee434a35697949bce1/vela3v_encoder.py), [span decoder](https://huggingface.co/vllm-sr/vela3-fast-vision/blob/c1f651cafddca43860a855ee434a35697949bce1/span_decode_v2.py).

The original modules implement the requested capabilities. This release adapts them directly. Each text adapter includes trained LoRA matrices, all fully updated layer parameters, normalization and cosine word/label readout. The span question text influences routing, but the upstream span schema itself is assembled from label descriptions and state segments; the JS port preserves that behavior.

Vision image-hallucination and OCR use `model.safetensors`; regions use `backbone_v2.safetensors`; ordinary decisions use `backbone_h2.safetensors`. Each adapter export carries its own image encoder and text/readout graph. We deliberately do not reuse image features across different task backbones. LoRA matrices remain explicit graph operations rather than being quantized or approximated.

The JS answer exposes `head` and `threshold`; the Python-only prose field `head_reason` is omitted.

Character offsets are reconstructed through the reversible ByteLevel BPE token bytes and mapped to Unicode code points. Word splitting, unit voting, gap filling, trimming, thresholds and temperature are ported from the original functions. The tests include emoji, CJK, combining characters, URL punctuation, email addresses, literal special tokens and Python-specific whitespace. The pinned tokenizers have no text normalizer; unsupported byte alignment fails explicitly.

The region decoder reshapes local tile scores, averages them with the resized global 8×8 scores, selects the maximum, and extracts its four-connected component at 0.7×peak. Box coordinates and peak-cell center are normalized to image dimensions.

## What the test proves

For each adapter, the chain runs from the original Python output and logits through the portable PyTorch wrapper and ONNX Runtime CPU to the JavaScript preprocessing and decoding. Python export gates logits/features; Node/Bun/Chromium tests additionally require exact token IDs, positions, span boundaries/labels/text, or region box and point. Span scores and confidence are compared numerically. Fixture input and original expected output are included.

Text: two end-to-end fixtures per adapter (10 total). Vision: one rendered image fixture each for hallucination, OCR corruption and a region (3 total). These are implementation parity fixtures, **not a representative quality benchmark**. Existing v0.1 decision reports remain historical under `reports/fast`, `reports/vision` and `reports/browser-*.json`; they are not counted as new adapter tests.

The automated summary and per-runtime measurements follow in `reports/tasks/summary.json` and the table below.

## Deliberate limits

The measurements below are FP32. The `q8` and `q4` variants are gated separately against these FP32 fixtures (`scripts/verify-quantized.ts`, see [models.md](models.md)); the real-model e2e (`E2E_MODELS=real make e2e`) also runs the documented `q8` examples in Chromium and WebKit. Default 2,048 input tokens. Long-document window aggregation is not implemented. Vision answer/OCR limit is 768 tokens with explicit rejection. No batch inference. One image for task adapters. The table below is the CPU and single-threaded WASM run; the WebGPU runs follow in [WebGPU](#webgpu). Firefox, mobile browsers, GPUs other than the Apple M-series one, and quantized adapter quality are unverified.

Images use the existing deterministic Lanczos preprocessing. JPEG decoding and color-management differences across platforms can change pixel values; for strict reproducibility use the included PNG fixtures or identical raw RGB arrays. OCR field objects use deterministic flattening; supplying the exact OCR string gives the clearest offset contract.

A successful parity test means ONNX reproduces the model's output. It does not mean every flagged word is an error, that OCR is extracted, or that a box is precise enough for a particular application. The upstream models are English-oriented. Large FP32 downloads and CPU image latency remain constraints even with one adapter resident at a time.

## Browser loading format

The initial embedded-weight FP32 `fast-ner` graph failed Chromium session creation with `std::bad_alloc`. The final export uses ONNX external data: the small `.onnx` protobuf references a sibling `.onnx.data` file. This changes storage only; tensor values are unchanged. The native and browser loaders both consume the same final packages. Node/Bun were rechecked after repacking. The Python exporter now applies this packaging before mandatory ONNX parity checks. See [ONNX Runtime Web: large models](https://onnxruntime.ai/docs/tutorials/web/large-models.html) for the 4 GiB WASM address-space constraint and external-data contract.

Do not rename or omit `.onnx.data` files. Model URLs and weights must be served together. This resolves the observed session-loading failure; it does not remove RAM limits for long inputs or constrained devices.

The final `export_tasks.py` was also rerun from the pinned source for `fast-ner`. Both the ONNX graph and external weight file were byte-identical to the browser-tested package (`export-reproduction.json`). The Node provider example completed NER, PII, OCR and region calls in that order with adapter disposal between tasks.

The browser provider also passed NER, PII, OCR, region and NER again within a single page/engine process (`browser-provider.json`), including release and reload of adapters. The visible region demo was exercised through its file input and Run button; its screenshot is `reports/tasks/demo-region.png`. These provider timings include session loading.

## WebGPU

On 2026-11-08 every real bundle (8 FP32, 8 `q8`, 6 `q4`) passed the same gates on WebGPU, on one Apple M-series Mac: in Node.js 26.11.1 through `onnxruntime-node`'s WebGPU provider, in Chromium 156.0.8078.4 (new headless mode) and in WebKit 27.2 (Playwright), both with `onnxruntime-web` 1.31.1. Decoded boundaries, labels, text, boxes and points matched exactly; the FP32 errors below are of the same size as on the CPU. Records: `reports/tasks/browser-*-webgpu.json` and `webkit-*-webgpu.json`.

Later the same day the four text `q4` bundles (evidence, relation, span, span_set) were replaced by GPTQ exports that load a shared backbone file from `models/backbone/fast/q4/` (`python/quantize_gptq.py`). They passed the quantized gate again in Node.js on the CPU and on WebGPU, in Bun, in Chromium on WASM and on WebGPU, and in WebKit on WebGPU, with largest score drifts of 0.003 to 0.015 (`reports/quantization-tasks.json`).

On 2026-11-09 the `vision-span` and `vision-ocr` `q4` bundles were replaced the same way (`python/quantize_gptq_vision.py`): GPTQ exports that load the image encoder and the text backbone from two shared files in `models/backbone/vision/q4/`. They passed the quantized gate in the same six runs, with largest logit errors of 0.061 and 0.629 against 0.597 and 1.317 for the replaced bundles, and largest score drifts under 0.001 (`reports/quantization-gptq-vision.json`).

The first fixture of a page includes compiling the WebGPU shaders. CoreML, the other accelerated provider of `onnxruntime-node` on macOS, failed the vision gate (logit error 0.020 > 0.015) and took 127 s for 1,800 text tokens, so the loaders do not use it. Speeds and settings: [performance.md](performance.md).
